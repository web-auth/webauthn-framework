Usernameless (discoverable) WebAuthn Demo

Like the basic-demo, but the sign-in page does not ask for a username. The browser surfaces a Conditional UI passkey picker and the server identifies the account from the credential id alone.

1. Register a discoverable passkey

Creates an account secured by a passkey with residentKey: required and userVerification: required. The user handle is stored on the authenticator so the browser can offer this account on a future sign-in without being told a username.

2. Sign in without a username

No username field. The browser picks a passkey from its autofill suggestions or the Conditional UI prompt, and the server identifies the account from the credential id and the authenticator-returned user handle.

3. Manage passkeys

List, add, rename and delete passkeys for the signed-in account. Same UI as the basic-demo.

How it differs from the basic-demo

  • Registration sets residentKey: required and userVerification: required, so the credential is discoverable.
  • Login options are issued with an empty allowCredentials list and the page calls navigator.credentials.get({ mediation: 'conditional' }). The user agent surfaces a passkey picker tied to the username input's autofill suggestions.
  • On verify, the server resolves the account from the credential id and validates that response.userHandle matches the binding stored at registration.

What this demo deliberately leaves out

  • A real database (JSON files under var/).
  • Account recovery, email verification, CSRF, rate limiting, ...
