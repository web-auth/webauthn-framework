WebAuthn Signal API Demo

The W3C Signal API lets a relying party tell the user agent that some local passkey-manager state is out of date. Three methods are demonstrated:

  • PublicKeyCredential.signalUnknownCredential after the user deletes a passkey on the server, so the passkey manager can prune the corresponding entry.
  • PublicKeyCredential.signalAllAcceptedCredentials after any change, to send the authoritative list of valid credential IDs for the user. The manager prunes anything not in the list.
  • PublicKeyCredential.signalCurrentUserDetails after a profile rename, so the manager shows the up-to-date name / displayName the next time the user picks this passkey.

Server-side, the API is just data plumbing: the page asks /api/account/signal-payload for the current authoritative snapshot, then makes the JS calls itself. No new validation runs on the server.

Browser support

The Signal API is recent. Chrome 132+, Edge 132+, Safari 18+. Firefox is trailing. The account page detects support and reports what each call did.
