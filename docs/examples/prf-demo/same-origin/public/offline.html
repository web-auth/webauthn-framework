Offline vault — no fetch after first load

This page does not register passkeys. The credential id and the two PRF salts must already be in this browser's localStorage — which is the case as soon as you have completed /register.html on this same browser (that page mirrors {credId, prfSalt, prfSalt2} into localStorage automatically after a successful register).

From there everything happens client-side: navigator.credentials.get() runs with a locally-generated challenge against rpId = location.hostname, the two PRF outputs become an AES-GCM key and an HMAC-SHA256 key, and ciphertexts live in localStorage. A service worker caches the page on first load, so you can disconnect (or hit airplane mode) and reload — everything keeps working.

⚠ If you delete the passkey or clear the site data, your encrypted items are gone forever. See the home page for the full caveat. This page is a learning aid, not a production design.
