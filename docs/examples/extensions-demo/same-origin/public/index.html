WebAuthn / CTAP authenticator extensions — playground

A minimal end-to-end demo for four extensions web-auth/webauthn-lib exposes: credProps, credProtect, credBlob / getCredBlob, and minPinLength. The registration page lets you toggle each one and shows what the user agent / authenticator actually returned. The assertion page exercises getCredBlob to retrieve the bytes you stored at registration.

ExtensionSpecWhat it does
credProps WebAuthn L3 §10.1.3 The user agent reports back rk (true if a discoverable credential / passkey was created) and an optional authenticatorDisplayName hint.
credProtect CTAP 2.1 §12.1 Pin one of three protection policies on the credential. The authenticator returns the policy it actually applied, so you can detect silent downgrades. Use enforce to fail registration rather than downgrade.
credBlob / getCredBlob CTAP 2.1 §12.2 Store ≤32 bytes of opaque data alongside the credential at registration time and ask for them back during a later assertion.
minPinLength CTAP 2.1 §12.4 Retrieve the minimum PIN length configured on the authenticator (only returned when the relying party id is on the authenticator's enterprise allow-list — otherwise absent).

Walk-through

  1. Open the registration page.
  2. Pick a username, optionally pick a credProtect policy, and optionally type a credBlob payload (≤32 bytes). All four extensions are requested at the same time; the table at the top of the page summarises what came back.
  3. Open the assertion page. Pick the credential you just registered. The authenticator returns the credBlob bytes, decoded and shown as base64url + UTF-8 (when the bytes are valid UTF-8).

Why a single demo

Each of these extensions is a few-line addition to a registration ceremony — a separate demo per extension would mostly duplicate the other one's plumbing. They also pair naturally: credProps.rk tells you whether your credProtect policy is actually meaningful (a non-discoverable credential cannot be enumerated, so userVerificationOptionalWithCredentialIDList is moot), and minPinLength is the only one a relying party can rely on without provisioning additional state.
