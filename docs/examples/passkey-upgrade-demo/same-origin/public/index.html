Passkey Upgrade Demo

Real-world rollout pattern: accounts start with a classic username and password, then the user is offered to enrol a passkey for faster sign-in. Future logins can use either factor; deleting every passkey is harmless because the password fallback is still there.

1. Sign up

Create an account with a username, a display name and a password.

2. Sign in

Authenticate with the password, or, if you have enrolled one, switch to a passkey directly from the login form.

3. Upgrade to passkey

Once signed in, your account page offers to add a passkey. The next sign-in then has the option to skip the password entirely.

What this demo demonstrates

  • Password sign-up and sign-in (hashed with password_hash / verified with password_verify).
  • Post-login passkey enrolment, the most common real-world rollout.
  • A login page that supports BOTH factors so users can migrate at their own pace.
  • Why deleting the last passkey is fine here (the password is still a usable fallback), unlike the basic-demo.

What this demo deliberately leaves out

  • Email verification, password reset, account recovery.
  • Step-up re-auth before passkey enrolment. A production RP would require the user to re-enter their password (or a recent strong factor) right before adding a passkey, otherwise a stolen password would let an attacker silently bind their own passkey.
  • Rate limiting, CSRF, password policy beyond minimum length.
